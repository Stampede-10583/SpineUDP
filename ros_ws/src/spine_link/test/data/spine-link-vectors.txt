# Spine link golden vectors. Shared by the Java tests (SpineUDPTest.goldenVectorsMatchSharedFile)
# and the C++ tests (spine_link). Both ends encode each packet from its field values and must
# produce exactly the bytes in `expect`, then decode `expect` back to the same values bit-for-bit.
#
# Format: one packet per line, whitespace-separated:
#   <stream> <name> <field>=<value> ... expect=<hex>
#   stream:  odom (Stream 1, 64 B) | pose (Stream 2, 40 B) | trig (Stream 3, 88 B)
#   fields:  in wire order. int64 fields (seq, packetSeq, triggerSeq[i]) are decimal integers.
#            float64 fields are either decimal or C99 hex-float (e.g. 0x1.921fb54442d18p1), which
#            Java Double.parseDouble and C/C++ strtod both parse exactly; Python needs
#            float.fromhex for the hex form.
#   expect:  the whole packet, little-endian, as lowercase hex (2 digits per byte, byte 0 first).
#
# trig vectors are real trigger-table states (triggerSeq consecutive from 0, -1 sentinels with a
# 0.0 timestamp), so the Java TriggerRing can reproduce them.
#
# Keep in lockstep with VisionLinkProtocol, ros_ws/src/spine_link/include/spine_link/protocol.hpp
# and docs/spine-link.md. Adding a vector is fine; changing an existing one means the wire format
# changed.
